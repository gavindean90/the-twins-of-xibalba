# Data contract (version 1)

All JSON is UTF-8. Metadata paths are relative to `corpus/`; adaptation paths are relative to the repository root. JSON arrays are used rather than an application-specific database. The executable validator is the dependency-free schema and integrity checker.

- **Source:** `id`, `title`, `publication_year` (integer or null), `contributors`, `languages` (ISO codes), `kind`, `catalog_urls`, `notes`, `acquisition_status`, `text_quality`, `review_date`, `asset_ids`. Manuscript creation date is separate from publication date.
- **Asset:** `id`, `source_id`, `path`, `url` (null only for generated output), `kind`, `quality`, `tracked` (boolean), `review_date`, `status`, `bytes`, and `sha256` or `upstream_checksum`. Generated files also identify `generated_from`. SHA-256 is required for committed files. A facsimile is not a transcription.
- **Rights:** `source_id`, `jurisdiction`, `status`, `publication_year`, `contributors`, `basis`, `evidence`, `components`, `international`, `limitations`, `review_date`. Status is `public_domain`, `CC0-1.0` or `copyrighted_reference_only`. Linked visuals without assets instead carry their own `image_rights` and pending state in the catalog; acquisition requires a rights record.
- **Relationship:** `id`, `from`, `to`, `relationship`, `certainty` (`verified` or `qualified`), `evidence`, `note`. The arrow points from a derived edition toward its witness.
- **Character:** `id`, `name` (editorial display label), `variants` with edition-specific spelling, `source_id` and verification note. Display names are not etymological claims.
- **Event:** `id`, `label`, `character_ids`, `status`. IDs identify editorial research topics, not alleged ancient chapter numbers.
- **Passage:** `id`, `event_ids`, `witnesses`, `adaptation_refs`, `uncertainty`, `alignment_level`, `editorial_status`. Witnesses identify a source, section, printed pages (or null), local line range and excerpt SHA-256 when mapped. `unmapped` records have no invented locator. These initial records align episodes, not individual sentences.
- **Installment:** `id`, `source_id`, `volume`, `issue`, `date` (YYYY-MM), inclusive printed `pages`, `text_asset_id`, `facsimile_asset_id`, `catalog_url`, `verification`, `ocr_method`, `ends_mid_page`.

`acquired` assets are committed. `download_verified` scans were fully downloaded and hashed during this build but omitted from Git. `remote_manifest_verified` scans have provider metadata and a checksum but were not downloaded. Edition-level acquisition states distinguish text-plus-scan recipes, manuscript facsimile-only, incomplete translation coverage, pending acquisition and linked-only modern references. The inventory must not collapse these into a single “complete” flag.

Line-anchor hashes use SHA-256 of UTF-8 text joined with LF, without a trailing newline, after Python `splitlines()`. Whole-file hashes cover exact bytes, including original line endings. IDs remain stable as coverage improves; do not repurpose an existing ID for a different episode.

## Selected manuscript extension (backward-compatible)

Existing source, event and passage IDs remain unchanged. The following additive records do not make a complete manuscript transcription or sentence alignment.

- **Folio map:** `metadata/ximenez-folios.json` has `schema_version: 1`, `source_id`, `scope` and `records`. Each record has an ID, source, pinned `facsimile_asset_id`, provider `image_sequence` and `image_url`, `viewer_url`, separate one-based `pdf_page`, `folio` (number, r/v side, visible mark, observation status and basis), language columns, event IDs, observation, review and uncertainty. The source sequence manifest is not replaced. The validator checks sequence/URL agreement, unique images and folios and referential integrity. It does not infer foliation from an arithmetic offset or certify pixel equivalence between the PDF and separately hosted JP2s.
- **Diplomatic reading:** `metadata/transcriptions.json` records `id`, source, `folio_map_id`, column, approximate `region_pdf_points` in top-left coordinates, `diplomatic_asset_id`, method, review date/status and uncertain readings. `normalized_working_text` is null in this release and `transformations` empty; future normalized text requires a nonempty transformation record. `english_research_gloss` and `gloss_status` form a separate interpretive layer. The asset records the pinned facsimile as its generation input. There is no unsupported claim of independent review: the only presently allowed review status is `agent_image_checked_not_independently_reviewed`. A future independently reviewed state requires reviewer evidence and an explicit schema extension.
- **Image witness:** `status: verified_image_location` has null `asset_id` (not a text anchor), plus `manuscript.folio_map_id`, column and region note. Resolve the actual facsimile through the folio record. This establishes an inspected PDF page's episode presence; provider correspondence limitations remain in that record. Text witnesses retain `verified_text_location`, line ranges and excerpt checksums. A diplomatic text witness also has `transcription_id`.
- **Alignment:** new witnesses have `alignment_type` (`close_textual`, `episode`, `interpretive` or `unmapped`) and `confidence` (`low`, `medium` or `high`). Confidence concerns the claimed alignment, not every source word or historical interpretation. `close_textual` is used only for the small diplomatic excerpts; broad narrative matches remain `episode`. An interpreted parallel is not silently upgraded to manuscript corroboration. Existing witnesses without these optional fields retain their original status and explanatory relationship.

`partial_transcription_facsimile_download_verified` distinguishes the manuscript's new limited text holdings from complete text acquisition. Event status can now describe selected image checking with linguistic review pending, or printed parallels without manuscript collation. Detailed qualifications live in passage witnesses and dossiers; neither status asserts expert verification.
